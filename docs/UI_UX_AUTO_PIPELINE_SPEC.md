# Logta | لُقطة — UI/UX Spec for the Automatic Scanning Pipeline

Status: **specification only** (no production UI changed). Branch `ui-ux-auto-pipeline`, from `origin/main` `0a15fec`.
Source of truth for data: `docs/API.md`, `docs/DATA_MODEL.md`, `server/app.ts`, `src/lib/*`.
Design language is unchanged: see `docs/UI_UX_HANDOFF.md` (palette, Inter + IBM Plex Sans Arabic, 44px targets, RTL via logical utilities, `.btn` / `.card` / chips).

---

## 0. Golden rules for this phase

1. **Never show saved data as "awaiting approval".** The automatic backend saves prices immediately. Use *Saved*, *Held*, *Waiting*, *Unknown*. Never *Confirm* / *Pending approval* for anything the server already stored.
2. **Keep the Confirm / Reject flow working today.** `VerificationTable` stays as is until the team confirms the API is integrated and tested.
3. **Estimates are never presented as real.** See section 7.
4. **Be honest about time.** The API has no progress events, so the processing screen never fakes percentages.

## 1. Manual flow vs automatic API flow (decision sheet for the frontend developer)

| | **Manual flow (in `main` today)** | **Automatic API flow (`POST /api/scan`)** |
|---|---|---|
| Extraction | Browser → `api/extract` (serverless proxy) | Server: AI call 1 (extract) + alias cascade + AI call 2 only for unresolved lines |
| Matching | `productMatcher.ts` in the browser, against the **local 28-product catalogue** | Server DB: **147 products, 12 stores, integer ids**, learned aliases |
| Human step | User confirms / rejects every line | **None.** Prices are recorded on arrival |
| Persistence | `localStorage` (`applyScan`) | SQLite on the server, shared by all devices |
| New products | Draft created locally on confirm | Created automatically after 3 sightings by 2+ devices (AI proposal required) |
| Outlier prices | Not detected | Quarantined (>35% off the 30-day median) until a second shopper confirms |
| Alerts / optimiser | Not available | Available (`/api/alerts`, `/api/optimize`) |
| Identity | None | Anonymous `deviceId` generated by the app |
| Failure modes | Simulated fallback | 400/403/413/429/502/503, `partial` reports, lines waiting for AI retry |
| Demo risk | Works offline, deterministic | Needs the server running on a host with a persistent disk, CORS, and an AI key |

### Decisions the frontend developer must make (recommended defaults in bold)

| # | Decision | Recommendation for the hackathon |
|---|---|---|
| D1 | Which flow is the live demo path? | **Keep manual as the default; add the automatic flow behind a flag (`VITE_API_BASE` set = automatic).** If the server is down at demo time, the app still works. |
| D2 | One catalogue or two? Local ids (`'mishref-coop'`) and server ids (`3`) differ. | **When automatic is on, the server is the only catalogue.** Do not mix local seed products with server products. |
| D3 | Does the manual review screen survive? | **Yes until D1 flips.** Afterwards it becomes an optional "Report a mistake" (API docs: "can come later"). |
| D4 | Failure fallback: when `/api/scan` returns 503/502/network error, fall back to the manual flow or show an error? | **Show the error state (section 4) with Retry; offer "Use demo receipt" only in demo mode.** Silent fallback would mix local and server data. |
| D5 | Where does "Recent prices" come from? There is **no recent-scans endpoint**. | **"Your recent scans" from the scan reports stored locally per device, plus "Browse prices" via `GET /api/products`.** Or ask Abdullah for `GET /api/prices/recent`. |
| D6 | Location for the optimiser | **Geolocation with an "area picker" fallback** built from `GET /api/stores` (`area`). |

## 2. Recommended scanner user journey

**Today (manual, unchanged):** Upload → Scanning → Review (Confirm / Reject) → Success → feed.

**Automatic (target):**

```
Home (upload + optional store) → Processing → Scan result ("Receipt saved")
                                              ├─ all good → Done: Scan another
                                              ├─ some lines waiting / unknown / held → same screen, grouped sections
                                              └─ partial (store unknown) → "Choose store" step → Scan result
                              └─ any error → Error screen (retry, keep photo)
```

Result screen **replaces** the review screen; there is no Confirm button because nothing is awaiting approval. The only user action that can still change the outcome is *choosing the store* when the server could not tell.

## 3. Status vocabulary (API → UI)

Report-level `status`: `processed` | `partial` | `failed`. Line-level `status`: `matched` | `needs_review` | `unmatched`. Observation `status`: `accepted` | `quarantined` | `rejected`.

| API state | What it really means | UI label (EN / AR) | Chip colour | Icon | Counts as saved? |
|---|---|---|---|---|---|
| line `matched` + obs `accepted` (`no_history`, `within_range`, `confirmed_by_independent_observation`) | Price recorded and used | **Saved** / **تم الحفظ** | mint (`brand-light` / `brand-dark`) | `CheckCircle2` | Yes |
| line `matched` + obs `quarantined` (`outlier_quarantined`) | Recorded but excluded from current prices until another shopper confirms | **Held** / **قيد التحقق** | amber | `ShieldAlert` | Stored, not yet counted |
| line `needs_review` | AI was unavailable; server retries every 5 min | **Waiting for AI** / **بانتظار الذكاء الاصطناعي** | slate | `Clock` | No |
| line `unmatched` (+ `pendingId`) | Unknown item; becomes a product after 3 sightings by 2+ devices | **New item** / **منتج جديد** | sky (same as the current "New product" chip) | `PackagePlus` | No (backfilled later) |
| obs `rejected` | Reserved, nothing sets it yet | Do not design now. Fallback label: **Not used** / **غير مستخدم** | slate | `Ban` | No |
| report `partial` (store `null`) | Lines matched, **no prices recorded** | **Store needed** / **نحتاج اسم المتجر** | amber banner | `Store` | No |
| report `failed` | Nothing usable | Error screen (section 4) | red | `AlertTriangle` | No |

Match method (`alias_exact` / `alias_fuzzy` / `llm` / `none`) is **secondary**. Show it only as a small grey caption: exact = no caption, fuzzy = "Matched by similarity" / "مطابقة بالتشابه", llm = "Matched by AI" / "مطابقة بالذكاء الاصطناعي". `aliasLearned: true` feeds the summary line "We learned N new spelling(s)" / "تعلّمنا N طريقة كتابة جديدة" (a pitch moment, not a per-line badge).

## 4. Screen specifications

### 4.1 Upload (home)

Keep the current camera-first card and gold sample card. Changes:

- **Optional store selector** (collapsed row under the buttons): "Store: auto-detect ›" opens a bottom sheet listing `GET /api/stores` (name EN/AR, area). Sent as `storeId`. Copy: *"Not sure? Leave it on auto-detect."* / *"غير متأكد؟ اترك الاكتشاف التلقائي."*
- **Privacy line** under the buttons (the server keeps no images, `image_deleted = true`): *"Your photo is deleted after we read it."* / *"تُحذف صورتك بعد قراءتها."*
- Disabled state with countdown while rate-limited (see 429 below).
- The new live-camera component (`CameraCapture.tsx`) is on main and **not yet design-reviewed**. Check it against 44px targets, RTL and the palette before demo.
- `deviceId` is invisible to the user.

### 4.2 Processing

Reuse `ScanningAnimation`. No stage percentages (the API gives none).

| Elapsed | Title | Body |
|---|---|---|
| 0–8 s | **Reading your receipt…** / **نقرأ فاتورتك…** | *We match every line to the Kuwait catalogue and save the prices.* / *نطابق كل بند مع كتالوج الكويت ونحفظ الأسعار.* |
| 8–25 s | **Still working…** / **ما زلنا نعمل…** | *The AI is taking a little longer than usual.* / *الذكاء الاصطناعي يستغرق وقتاً أطول من المعتاد.* |
| >25 s (dev sets timeout) | Error screen: timeout | |

Add a **Cancel** text button (44px) that aborts the request. The server may still save the scan; say so in the cancel confirmation only if the developer confirms this behaviour.

### 4.3 Scan result (replaces `VerificationTable` in automatic mode)

Hierarchy (top to bottom):

1. **Hero** (reuse the success hero): check icon, **"Receipt saved"** / **"تم حفظ الفاتورة"**, store name (`storeNameEn` / `storeNameAr`). Use "Receipt processed" if some lines are not saved yet.
2. **Summary tiles** (2×2 on mobile): *Saved* · *Held* · *Waiting* · *New items*. Hide any tile that is 0 except *Saved*. Counts are computed from `lines[]` (statuses above), not invented.
3. **Learning line** (only if `learnedAliases > 0`): sparkle icon + *"We learned N new spelling(s). Next time this is instant."*
4. **Alerts card** (only alerts where `alert.userId === report.userId`; the report also contains other shoppers' alerts): gold-tinted card, bilingual `messageEn` / `messageAr` by language, CTA *View alerts*.
5. **New product card** (if `autoPromoted` is non-empty): *"X is now in the Logta catalogue."* Shape of `AutoPromotion` to be confirmed (see section 9).
6. **Line groups**, each a `.card` with a section header and count:
   - *Saved* (collapsed to 5 rows + "Show all N")
   - *Held — unusual price*
   - *Waiting for AI*
   - *New items*
7. **Sticky bar** (same offset as today, `bottom-[calc(5.5rem+env(safe-area-inset-bottom))]`): primary **Scan another**. No Confirm button.

**Line row**: product name (`productNameEn/Ar`, else `rawText` with `dir="auto"`), unit price `0.550 KD` (`dir="ltr"`, 3 decimals, `text-base font-extrabold`), status chip, optional grey caption (match method). Held rows add one explanatory sentence: *"This price looks unusual compared with recent ones. It will count once another shopper confirms it."* / *"يبدو هذا السعر غير معتاد مقارنة بالأسعار الأخيرة. سيُحتسب عند تأكيده من متسوق آخر."* Include `referenceMedian` as *"Usual price about 0.600 KD"* when present.

**Partial: store unknown** (report `status: partial`, `storeId` null): full-width amber card above the groups, *"We couldn't tell which store this is. Choose the store so we can save the prices."* / *"لم نتمكن من معرفة المتجر. اختر المتجر لنحفظ الأسعار."* Store select (48px) + primary **Save prices** (re-sends with `storeId`; the frontend must keep the photo in memory). Lines appear below in a muted state; the tiles show *Saved 0*.

**Waiting-for-AI note** (when any `needs_review`): *"N line(s) will be finished automatically. You don't need to do anything."* / *"سيتم إنهاء N بند تلقائياً. لا حاجة لأي إجراء."* (The API has no endpoint to poll a receipt; do not promise a visible update.)

**Unknown-items note**: *"Nobody has scanned these before. They'll be added once a few shoppers have."* / *"لم يمسحها أحد من قبل. ستُضاف عندما يمسحها عدد من المتسوقين."*

### 4.4 Errors, server failures and retry

One reusable **ErrorState** card (icon in a tinted circle, title, one-sentence body, primary button, optional secondary). The photo is kept so **Retry** never re-uploads.

| Case | Title (EN / AR) | Body (EN / AR) | Primary / secondary |
|---|---|---|---|
| 400 not an image / mismatch | **We can't read this file** / **لا يمكننا قراءة هذا الملف** | *Use a JPG, PNG or WEBP photo.* / *استخدم صورة بصيغة JPG أو PNG أو WEBP.* | Choose another photo |
| 400 `Extraction…` (AI output unusable) | **We couldn't read this receipt** / **لم نتمكن من قراءة الفاتورة** | *Try again with better light and a flat page.* / *جرّب مرة أخرى بإضاءة أفضل وورقة مسطحة.* | Retry / New photo |
| 413 too large | **That photo is too large** / **الصورة كبيرة جداً** | *Try a smaller photo.* / *جرّب صورة أصغر.* | Choose another photo |
| 429 per-minute | **Slow down a little** / **تمهّل قليلاً** | *You can scan again in {n} s.* / *يمكنك المسح مرة أخرى بعد {n} ثانية.* | Disabled Scan button with countdown from `Retry-After` |
| 429 hourly | **Scan limit reached** / **وصلت للحد الأقصى** | *Try again in about {n} min.* / *جرّب مرة أخرى بعد حوالي {n} دقيقة.* | OK |
| 502 AI failed | **The AI is having a moment** / **الذكاء الاصطناعي مشغول** | *Nothing was saved. Please try again.* / *لم يُحفظ شيء. حاول مرة أخرى.* | Retry |
| 503 no AI configured | **Scanning is unavailable right now** / **المسح غير متاح حالياً** | *Browse prices or try again later.* / *تصفّح الأسعار أو حاول لاحقاً.* | Browse prices |
| 403 origin / config | **Something is misconfigured** / **هناك خطأ في الإعداد** | *Please tell the team.* / *يرجى إبلاغ الفريق.* | (dev detail behind a "Details" toggle, dev builds only) |
| Network / timeout | **Can't reach Logta** / **تعذّر الوصول إلى لقطة** | *Check your connection and try again.* / *تحقق من اتصالك وحاول مرة أخرى.* | Retry |

Also: a slim **server-down banner** under the header on Basket / Alerts / Browse when `GET /api/health` fails: *"Live prices are unavailable. Showing the last data we have."* (only if the developer caches data; otherwise show the ErrorState).

Visual: red for hard failures (`bg-red-50`, `text-red-700`), amber for limits/retry, never full-screen modals.

### 4.5 Success and completion

Merged into 4.3. If every line is saved: hero *"Receipt saved"*, tiles, then **Scan another**. If **Saved = 0** (partial or all held/waiting), the hero becomes neutral (navy, `Clock` or `Store` icon, **"Receipt received"**) so we never show a green check over zero saved prices.

## 5. Basket Optimizer (new screen, replaces the placeholder)

**API:** `GET /api/products?q=` (search, `bestPrice`, `storeCount`) · `GET/POST /api/lists` · `POST /api/optimize` with `{ location:{lat,lng}, items:[{productId, qty, allowSubstitute}], maxStores? }` or `{ listId, location? }` → up to 3 plans `{ stores, itemsPerStore, subtotal, travelCost, travelKm, total, savingsVsBestSingleStore, missingItems, substitutions, avgTrust }` · `GET /api/stores`.

### 5.1 Step A: Build your basket

- **Header block**: title *"Basket Optimizer"* / *"تحسين السلة"*, subtitle *"Add what you need. We find the cheapest way to buy it."* / *"أضف ما تحتاجه ونجد لك أرخص طريقة لشرائه."*
- **Search field** (48px, search icon, clear button). Results (debounced) as a card list: name (EN/AR by language), size, *"from 0.550 KD at N stores"*, an **Estimate** chip when the best price is estimate-heavy (section 7), and an **Add** button (44px). Empty search: show a few popular products from `GET /api/products?limit=8`.
- **Basket list**: row = name, qty stepper (− / n / +, each 44×44), a **"OK to swap for a similar item"** switch (maps to `allowSubstitute`, default off), remove (44px). Empty state: illustration (basket in the green panel), *"Your basket is empty. Search above to add items."*
- **Location chip** under the list: *"Near: Mishref ›"*, tap opens a sheet: **Use my location** (browser prompt) and **Choose an area** (from stores' `area`). Until set, the primary button asks for it.
- **Sticky bar**: primary **Find cheapest plan** (disabled with a reason: *"Add at least one item"*), shows item count. Optional secondary **Save list** (stretch; `POST /api/lists`).

### 5.2 Step B: Plans

- **Loading**: three skeleton cards (no spinner-only screens).
- **Plan cards** (stacked; first one highlighted with a mint border and the badge **Best plan** / **أفضل خطة**):
  - Total `12.350 KD` (large, `dir="ltr"`).
  - Savings chip **only when `savingsVsBestSingleStore > 0`**: *"Saves 1.200 KD vs the best single store"* / *"توفّر 1.200 د.ك مقارنة بأفضل متجر واحد"*. Never show a savings chip for 0, never invent a baseline.
  - Store chips (name, area) and *"N stores"*.
  - Breakdown line: *"Items 11.750 · Travel ≈ 0.600 (about 7 km, estimated)"*. Travel is an estimate (straight-line × 1.3): always say *estimated*.
  - Confidence: `avgTrust` → *High / Medium / Low price confidence* (suggested thresholds ≥0.75 / ≥0.5 / below; the developer confirms against real values). If low: *"Mostly based on demo estimates."*
  - **Expand** (44px) shows `itemsPerStore` grouped by store: store header (name, area, online stores show *"Delivery X KD · min order Y KD"* from `deliveryFeeKwd` / `minOrderKwd`), rows with qty × unit price and line total.
  - **Swaps** (`substitutions`): *"Swapped X → Y"* in a sky-tinted row.
  - **Missing** (`missingItems`): amber row *"Not found in these stores: …"* / *"غير متوفر في هذه المتاجر: …"*.
- **Empty / error**: no plans → *"We couldn't build a plan. Try fewer items, or allow swaps."* ErrorState for 400/network (section 4.4). The 100-item limit gets a counter at 90+.

## 7. Demo estimates vs verified prices (one rule everywhere)

Applies to **feed, product prices, basket plans, alert cards**.

From `GET /api/products/:id` → each price has `sourceMix { receipt, shelf_tag, manual, seed, seedEstimate, seedWebSnapshot }`, `observationCount`, `trust (0–1)`, `lastObservedAt`, `isPromo`.

| Condition | Label | Style | Also show |
|---|---|---|---|
| `seedEstimate / observationCount ≥ 0.5` | **Demo estimate** / **تقدير تجريبي** | gold-light, dashed gold border, `FlaskConical` | **No** trust %, **no** timestamp, **no** price-change arrows (the history is seeded) |
| mostly `seedWebSnapshot` | **Web snapshot** / **لقطة من الويب** | slate chip | date of snapshot if available |
| otherwise (receipt / shelf tag dominant) | **Verified** / **موثّق** (+ **Receipt** / **Shelf tag** badge) | mint | trust bucket (High ≥0.75 / Medium ≥0.5 / Low), "Updated 2 d ago" (`lastObservedAt`), arrows only between real observations |
| `isPromo` | **Promo** / **عرض** | gold | |

- A page that mixes both (e.g. a product with one estimate store and one verified store) shows each row with its **own** label. Never a single label for the whole list.
- Section headers: *"Verified prices"* above *"Demo estimates"*. The note stays: *"Prices marked "Demo estimate" are sample data for this demo, not real scans. Scan a receipt to add real prices."*
- Never use the words *verified*, *live* or *scanned* for estimate rows. The current feed title **"Recent Verified Scans"** must only list rows that came from this device's real scans.

### Feed changes

- "Your recent scans": the device's own scan reports (kept locally by the developer), newest first, using the Saved / Held / Waiting chips.
- "Browse prices": `GET /api/products?q=` list, row = name, *"from X KD · N stores"*, Estimate / Verified chip, tap → product detail (per-store prices, cheapest first, 30-day mini history from `history[]`).
- Optional pitch card from `GET /api/stats`: *"Logta is learning: N products grown from receipts · N spellings learned · AI needed for X% of lines this week"* (`grownFromReceipts`, `aliases.learned`, `last7Days.aiShare`). Only show real numbers; hide the card if the call fails.

## 8. Frontend developer integration requirements

1. `deviceId`: `crypto.randomUUID()` in `localStorage`, created once.
2. `API_BASE = import.meta.env.VITE_API_BASE`; the API client returns a typed error `{ status, message, retryAfter? }`. Parse the `Retry-After` header for 429.
3. Keep the compressed photo in memory until the scan is finished (needed for Retry and for "Save prices" after choosing a store).
4. Map the scan report to the UI states in section 3 from `lines[]`; do not use `counts` for the tiles.
5. Filter `report.alerts` by `userId === report.userId` before showing alerts.
6. Replace the local catalogue and stores with `GET /api/products`, `/api/stores` when automatic mode is on (D2). Product names come from `nameEn`/`nameAr`.
7. Add i18n keys for every string in this document (EN + AR in `src/i18n.ts`), reusing existing naming (`sample…`, `status…`, `help…`).
8. Do not delete `VerificationTable` or the `applyScan` path until the flag flips.
9. Server hosting: persistent disk (Replit / Railway / Render with disk / VM), `ALLOWED_ORIGINS` includes the front-end origin, an AI key is set (otherwise `/api/scan` is 503).
10. Reuse design tokens and classes from `docs/UI_UX_HANDOFF.md`. All new screens: 360 px and 390 px, EN LTR and AR RTL, targets ≥ 44px, sticky bars at `bottom-[calc(5.5rem+env(safe-area-inset-bottom))]`.
