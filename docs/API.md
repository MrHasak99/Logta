# Logta API server

The server is the piece that makes the idea work end-to-end: **people scan receipts, the AI sorts every line,
and the database grows and gets more accurate with every scan, with no human confirmation.**

```bash
npm install
npm run server          # http://localhost:8787  (PORT to change). Seeds the DB on first start.
```

It needs a host that **keeps the SQLite file** between requests: Replit, Railway, Render with a disk, Fly.io, or any VM.
Vercel serverless functions can't do this, because the file resets between invocations. The Vercel UI calls this
server over HTTPS (CORS allowlist below).

## Environment (`.env` in the repo root is loaded automatically)

| var | purpose |
|---|---|
| `OPENROUTER_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` | AI provider, first one set wins, the others are fallbacks (same names as `api/extract.ts`). Without a key, `/api/scan` returns 503; everything else works. |
| `LOGTA_LLM_MODEL` | optional model override for OpenRouter/OpenAI (default `gpt-4o-mini`) |
| `ALLOWED_ORIGINS` | comma-separated browser origins (default: `http://localhost:5173,5179,4173` + `https://logta-alpha.vercel.app`) |
| `ADMIN_TOKEN` | required header `X-Admin-Token` for `/api/admin/*`; if unset, admin routes only answer localhost |
| `LOGTA_DB_PATH` | SQLite file (default `data/logta.db`) |
| `PORT` | default 8787 |

## The automatic flow behind `POST /api/scan`

```
photo ─► AI call 1: extract lines (fixed server prompt)
      ─► alias cascade: exact / fuzzy match (free; no AI)
      ─► AI call 2, only for lines still unresolved: pick a product, or propose a new one (name EN/AR, brand, category, size)
      ─► price recorded (outliers quarantined, auto-accepted when a 2nd shopper confirms) ─► price alerts fired
      ─► unknown items collected ─► seen ≥3× by ≥2 devices + AI proposal → product created automatically
         (or merged into an existing one if the proposal matches it), and earlier receipt prices are backfilled
```

- Every confident AI decision (≥ 0.85) becomes an alias, so the next identical line is a free exact match.
  `GET /api/stats → last7Days.aiShare` shows the share of lines that needed AI, which falls as people scan.
- Unknown text is sent to the AI **once**: later sightings within 7 days reuse its decision and are just counted
  (`llmSkipped` in the scan report). This works even when no AI key is configured.
- If the AI is down, lines stay `needs_review`. The server retries every 5 minutes (also `POST /api/admin/retry`),
  and resolves them without AI if an alias was learned in the meantime.
- Identity is a stable anonymous **`deviceId`** generated by the app (e.g. `crypto.randomUUID()` in localStorage).
  No accounts. It lets the database count distinct contributors.

## Endpoints

All bodies and responses are JSON. Errors: `{ "error": "…" }` with 400/403/404/413/429/502/503.

### Scanning (needs a browser `Origin` from the allowlist; rate-limited 6/min per device, 60/min per IP)
| method & path | body | returns |
|---|---|---|
| `POST /api/scan` | `{ deviceId, imageUrl: "data:image/jpeg;base64,…", storeId? }` | scan report (below) |
| `POST /api/ingest` | `{ deviceId, extraction: ReceiptExtraction, storeId? }` (e.g. the output of `api/extract`) | scan report |

Scan report (abridged):
```json
{
  "userId": 4, "receiptId": 12, "storeId": 3, "storeNameEn": "Salwa Co-op", "status": "processed",
  "lines": [{ "rawText": "TILDA PURE BASMATI 5KG", "unitPriceKwd": 4.45, "status": "matched", "method": "alias_exact",
              "confidence": 1, "productId": 31, "productNameEn": "Tilda Pure Basmati Rice 5kg", "aliasLearned": false,
              "observation": { "id": 41231, "status": "accepted", "reason": "within_range" } }],
  "counts": { "alias_exact": 5, "alias_fuzzy": 1, "llm": 0, "none": 0, "needsLLM": 0 },
  "learnedAliases": 1, "quarantined": 0, "alerts": [{ "userId": 1, "hint": "lower_seen_recently", "alert": { "messageEn": "…", "messageAr": "…" } }],
  "pendingIds": [], "autoPromoted": [], "llm": "openrouter>openai", "llmCalls": 1, "llmSkipped": 0, "llmErrors": []
}
```
`status: "partial"` means the store couldn't be identified (prices not recorded; resend with `storeId`) or
some lines are waiting for an AI retry.

### Catalogue & prices
| method & path | returns |
|---|---|
| `GET /api/stores` | stores (coords approximate; online store has `deliveryFeeKwd` / `minOrderKwd`) |
| `GET /api/categories` | categories |
| `GET /api/products?q=&limit=` | search by any alias (EN, AR, Kuwaiti words like `عيش`, receipt shorthand), with `bestPrice` + `storeCount` |
| `GET /api/products/:id` | `{ product, prices[] (per store, cheapest first), stats30d, history[], aliases[] }` |

Each price has `priceKwd, trust (0–1), lastObservedAt, observationCount, isPromo, sourceMix`.
**Show estimates honestly:** if `sourceMix.seedEstimate` is most of `observationCount`, label it "estimate".

### Basket optimiser & lists
| method & path | body / query | returns |
|---|---|---|
| `POST /api/optimize` | `{ location: {lat,lng}, items: [{productId, qty, allowSubstitute}], maxStores? }` or `{ listId, location? }` | top 3 plans `{ stores, itemsPerStore, subtotal, travelCost, travelKm, total, savingsVsBestSingleStore, missingItems, substitutions, avgTrust }` |
| `GET /api/lists?deviceId=` | | the device's lists |
| `GET /api/lists/:id` | | list with items + products |
| `POST /api/lists` | `{ deviceId, name, items: [{productId, qty, allowSubstitute}] }` | created list (201) |

### Price alerts
| method & path | body / query | returns |
|---|---|---|
| `POST /api/watchlist` | `{ deviceId, productId, targetPriceKwd }` | watch (201) |
| `GET /api/watchlist?deviceId=` | | active watches with products |
| `GET /api/alerts?deviceId=&unseen=1` | | alerts (bilingual `messageEn` / `messageAr`) |
| `POST /api/alerts/:id/seen` | `{ deviceId }` | `{ ok: true }` |

### Health, stats, admin
| method & path | returns |
|---|---|
| `GET /api/health` | `{ ok, llm }` |
| `GET /api/stats` | catalogue size (`grownFromReceipts`), aliases (`learned`), receipts, observations by evidence, quarantined, pending, **`last7Days.aiShare` / `freeShare`** |
| `POST /api/admin/retry` | finish `needs_review` lines + auto-promote (admin) |
| `POST /api/admin/pending` | unknown items still collecting sightings (admin) |

## Hooking up the existing UI (when the team is ready)
1. Generate and keep a `deviceId` in localStorage.
2. Scanner: send the photo to `POST {API}/api/scan` (or keep `api/extract` and send its JSON to `/api/ingest`).
   Show the report instead of the confirmation screen. An optional "report a mistake" can come later.
3. Feed / prices: `GET /api/products` and `/api/products/:id`. Optimiser: `POST /api/optimize`. Alerts: `/api/alerts`.
4. Set `VITE_API_BASE` in Vercel to the server's URL, and add the Vercel URL to `ALLOWED_ORIGINS` if it differs.
